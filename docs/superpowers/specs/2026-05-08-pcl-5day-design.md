# PCL 5 天实践重组设计

## 目标

将当前仓库中零散的 Day 1 代码，重组为按天组织的 5 个独立 C++ 实践文件，目录清晰、注释完整、便于在 Visual Studio 的 Debug 模式下逐天学习和运行。

## 目录结构

```text
src/
├── day1/
│   └── day1_registration.cpp
├── day2/
│   └── day2_icp.cpp
├── day3/
│   └── day3_features.cpp
├── day4/
│   └── day4_segmentation.cpp
└── day5/
    └── day5_reconstruction.cpp
```

## 设计原则

1. 每一天只保留一个主 `cpp` 文件，避免初学者在多个入口文件之间跳转。
2. 每个文件都包含“大白话”中文注释，说明这一天做什么、为什么做、输入输出是什么、运行后会看到什么效果。
3. 参数默认偏保守和轻量，优先保证 Debug 模式下可以较快跑通。
4. 每天代码尽量承接前一天输出，构成一条连续学习路径。
5. 对于仓库中暂时缺少专用数据集的环节，先复用 Stanford Bunny 数据，并在代码中明确说明“这是教学演示版”。

## 每天实践的职责

### Day 1

- 内容：点云预处理 + SAC-IA 粗配准。
- 作用：把原始 Bunny 点云先降采样、去噪，再做大致对齐。
- 效果：生成清洗后的点云和粗配准结果，为 Day 2 精配准准备初始位姿。

### Day 2

- 内容：ICP / GICP 精配准。
- 作用：在 Day 1 粗对齐的基础上进一步迭代优化。
- 效果：得到更准确的配准结果与更稳定的变换矩阵。

### Day 3

- 内容：法向量、FPFH 特征和关键点演示。
- 作用：帮助理解点云局部几何描述方式。
- 效果：输出法向量与特征统计信息，为配准、识别和分割建立基础。

### Day 4

- 内容：RANSAC 平面分割 + 欧式聚类。
- 作用：把混合点云中的结构拆开，理解模型拟合和区域分离。
- 效果：得到平面内点、非平面点和聚类结果，观察不同结构被分离。

### Day 5

- 内容：基于法向量的简单表面重建。
- 作用：把离散点云转换成连续曲面或网格。
- 效果：输出可视化或保存用的网格结果，理解“点云到模型”的最后一步。

## 数据流

1. Day 1 读取原始 `bun000.ply`、`bun045.ply`。
2. Day 1 输出 `data/processed/*.pcd` 以及粗配准结果。
3. Day 2 读取 Day 1 输出做精配准。
4. Day 3 读取 Day 1 或 Day 2 的结果计算法向量和特征。
5. Day 4 在预处理后的点云上做分割和聚类。
6. Day 5 在清洗后的点云上做重建，必要时复用 Day 3 法向量。

## 性能策略

1. 统一先做体素降采样，控制点数规模。
2. ICP、SAC-IA、特征搜索半径和迭代次数使用教学版较小参数。
3. 默认关闭复杂可视化循环，先以文件输出和控制台统计为主。
4. 重建阶段优先选择参数更轻的教学方案，避免 Debug 下长时间等待。

## 冗余文件处理策略

### 推荐删除

- `src/day1_preprocess.cpp`
- `src/day1_sac_ia.cpp`

这两个文件会被 `src/day1/day1_registration.cpp` 替代，继续保留容易让入口文件重复。

### 建议保留

- `docs/day1_learning_notes.md`
- `.trae/specs/prepare-pcl-day1-learning/*`
- `tests/test_day1_sources.py`

这些文件虽然不是最终运行入口，但仍然提供学习说明、任务背景和基础校验信息。

## 测试策略

1. 先写结构测试，验证 5 个按天组织的 `cpp` 文件存在。
2. 再补关键内容断言，检查每个文件包含当天核心算法关键词。
3. 代码实现后执行对应测试，确保重组没有遗漏主要实践内容。
